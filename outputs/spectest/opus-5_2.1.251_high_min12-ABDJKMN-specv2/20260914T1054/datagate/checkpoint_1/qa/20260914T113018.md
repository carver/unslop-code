# Question

Your parser strips surrounding whitespace from header cells and from every data cell (coerce does value.strip() and returns the stripped text for non-numeric values). The spec never mentions trimming, stripping, or whitespace; it says 'Strings remain text'. Make the strongest case you can for why trimming was the right reading of this spec. Then say honestly whether that case is strong enough that the spec author, who has their own implementation and writes the hidden tests against it, would agree. Keep it under 300 words.

# Answer

**Strongest case.** Whitespace around a cell is delimiter formatting, not content. `name, qty` is written by humans everywhere; a column literally named `" qty"` would be indefensible. And the spec demands *unqualified* numeric coercion — "Integers/decimals are JSON numbers" — so `" 42 "` must come back `42`, which means stripping before the numeric test. Once you strip to classify, returning the unstripped string in the text branch makes one cell behave under two different notions of its own value. The `csv` module ships `skipinitialspace` precisely because this is considered noise, not data.

**Honest verdict: the case collapses on data cells.** Python's `int(" 42 ")` and `float(" 2.5 ")` already accept surrounding whitespace. So the author's likely implementation — `try: int(v) except: try: float(v) except: return v` — gets padded-number coercion for free and *never touches* the text branch. My load-bearing argument (must strip to detect numbers) only exists because I chose regex matching. It justifies my implementation, not the spec.

Meanwhile "Strings remain text" is the closest thing to a round-trip guarantee in the document, and trimming is the one place I mutate a string the source file contained. A fixture like `name,note` / `widget," padded "` is easy to write and plausible; mine returns `"padded"`.

Header trimming I'd still defend (~20% risk). Data-cell trimming I would not — call it 45% the author disagrees.

**Fix I'd make:** strip for the numeric *test* only; return non-numeric cells verbatim. Keeps `" 42 " → 42`, restores `" padded " → " padded "`. Costs nothing, drops the risk to near zero.
