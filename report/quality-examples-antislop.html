What spectest wrote, and what spectest+antislop wrote instead

Code Opus 5 wrote for the dev problems under the spectest prompt (min12-ABDJKMN), at the final checkpoint, spec v0. Tinted lines are what scb-check 0.1.3 flagged. The switch on each example shows what spectest+antislop (min13-ABDJKMNT, the same prompt plus the benchmark's anti-slop rule list under Implement) wrote for the same job in its own runs. Implementation files only.

How these were chosen. Not for the contrast. Each spectest example is the worst code of its kind in the twelve spectest runs by the tool's own numbers, picked before any spectest+antislop code was read: the highest-complexity functions, the function with the most flagged lines, the largest duplicated blocks. Only then was the code doing the same job found in the spectest+antislop runs and shown as it is. Six of the nine jobs came out cleaner in both spectest+antislop runs; the enum check is still pasted in both, the JSON loader is still two copies, and one run keeps its isinstance checks by spreading them.

Over all twelve runs of each prompt, implementation files, final checkpoint: functions over CC 10 go from 172 (37 of them over CC 20, the worst at 85) to 11 (none over 20, the worst at 17); ast-grep flagged lines from 9,346 to 3,459; duplicated implementation blocks from 91 to 25. Cloned test lines go from 10,726 to 6,289 and stay the largest number on the page: the rule list is under Implement, and the tests are written before it applies.
