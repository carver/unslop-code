SCBench Spec Patches

Every change made to a benchmark spec so far: 30 patches across five of the six dev problems, each a unified diff against the spec the benchmark ships (v0). Each entry shows the changed line before and after.

The spectest prompts have the agent keep a registry of every ambiguity it meets in the spec: the line, the readings, the one it chose, and a Risk from 0 to 100, its own estimate that the hidden tests take another reading. It writes that number before it has seen any test.

Under each changed line: the Risk on that question in the runs that read the line unpatched, chose against the tests (the tests the patch answers failed) and had the question in their registry. Each dot is one run, the tick is the median. Runs that failed the same tests without asking the question are counted beside it. A run whose entry chose the tests' reading and whose code failed them anyway is a slip, not a reading: it gets no dot and is named with its prompt. Which registry entry asks a line's question, and which way it chose, was settled by reading the entries, one run at a time.
