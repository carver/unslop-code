Unslop Results on Slop Code Bench

Use two strategies on six problems: tweak the spec if ambiguous, and use a new prompt, "spectest". Every figure is lower-is-better. Two runs per problem, using Claude Opus 5.

The spectest prompt replaces the benchmark's default, just-solve. Spectest guides the agent to write tests from the spec before implementing. The agent splits the spec into phrases, writes a test for each one, and logs every ambiguity. This spectest is my 12th version. In the code, it's called min12-ABDJKMN. Version 12 was split into chunks A to S, and then trimmed. The remaining bits are: A and B are shell tool hygiene, D writes tests from the spec, J and K log ambiguities, M and N speed up execution by running focused tests.

scb-check scores the test files along with the implementation, and spectest writes 3.8 times the test code. Over the whole snapshot its ast-grep share falls 67%; in implementation files alone it falls 18%. spectest also writes 26% less implementation, so the count of flagged implementation lines falls 38% (9,412 to 5,870). Erosion has the same shape with more left over: down 75% over the whole snapshot and 36% in implementation files. The rise in cloned lines is all in the tests; implementation clones fall from 0.040 to 0.030.

The human row is the mean over 27 of the 28 Major-tier repositories (over 10k stars) in the paper's v1, Table 2, at HEAD, split by the same tool. Humans write tests too, 58% of their lines, so their whole-repository figures are diluted the same way. Implementation against implementation, spectest's ast-grep share is 2.0 times the human one, its erosion is 0.36 against 0.44, and its cloned share is 0.030 against 0.079. Its tests are cloned 2.0 times as much as human tests. The human bars in the headline are this same rerun. v1's Table 2 gives 0.10 for ast-grep, which this scb-check version does not reproduce (0.063 here); its erosion mean, 0.31, it does (0.31).
